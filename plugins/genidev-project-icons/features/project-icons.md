# Иконки проектов

## Что делает

Ставит выбранную иконку слева от названия проекта в боковой панели bb и
оживляет её по состоянию проекта: агент работает — иконка водит глазами, агент
ждёт владельца — иконка озадачена, тред закончился ошибкой — испугана, закончился
успешно — рада; у состояний, кроме «работает», есть цветная метка в углу.

## Поведение

- Меню проекта (три точки) → «Icon» → боковое окно с одной сеткой, без
  разделов и заголовков. Порядок: «Без иконки», вшитые иконки в порядке
  `assets/icons/icons.json`, иконки личного набора, свои картинки в порядке добавления, последней —
  «+» с подсказкой «Добавить свою картинку».
- Клик по ячейке назначает иконку, «Без иконки» снимает. Изменение видно во
  всех открытых окнах bb сразу (realtime `changed`).
- На телефоне окно выезжает под пунктом, ячейки 44×44.
- Подчёркивание от «Цветов проектов»: побеждает последнее действие (см. ниже).
- При наведении (и фокусе с клавиатуры) на иконку в окне выбора видны её
  состояния (см. «Показ состояний при выборе»).

## Иконка новому проекту (0.3.1)

- Плагин помнит идентификаторы проектов, которые уже видел (`seen_projects`), и
  сверяет их с `bb.sdk.projects.list()` при загрузке, при каждом запросе состояния и
  при событии `thread.created`. События создания проекта в SDK нет (есть только
  события тредов), поэтому сверка со списком — основной путь, событие треда
  лишь подталкивает её.
- При первом запуске версии все существующие проекты записываются как известные и
  иконку не получают (метка `baseline` в `icon_meta`; ставится, когда в списке есть
  хотя бы один проект). Новым считается проект, которого не было в списке.
- Иконка: из всей библиотеки (личный набор тоже), кроме `leader-*`, `star-*` и `sheikh` (константа `NEVER_AUTO` в `pack.ts`), та, что сейчас не стоит ни у
  одного проекта; среди свободных выбор по хешу (sha-256) идентификатора проекта;
  свободных нет — по тому же хешу из всех. Пустая библиотека: проект только
  запоминается.
- Назначение пишет `assigned_at`, ставит `auto = 1`, рассылает `changed` и пишет в
  журнал одну строку с идентификаторами проекта и иконки. Ручной выбор сбрасывает
  `auto`; «Без иконки» удаляет строку, а проект остаётся в `seen_projects`, поэтому
  автоматически иконка не вернётся.
- Настройка «Ставить иконку новому проекту» (по умолчанию включена). Выключена:
  новые проекты только записываются как известные и задним числом иконку не
  получают. Личные проекты bb не смотрятся.
- `bb genidev-project-icons list` помечает такие иконки «авто» (JSON: `auto: true`).

## Подчёркивание: последнее действие

Плагин цветов ставит на подпись проекта `data-pc-chosen-at="<мс>"`, когда
владелец выбрал цвет вручную. Плагин иконок хранит момент назначения иконки
(`assigned_at` в `project_icons`, в состоянии `assignedAt`; у назначений,
сохранённых до 0.2.1, и у проектов без иконки — 0). Подчёркивание скрыто (класс
`pi-no-underline` на элементе иконки, правило в `style.css`), когда есть иконка
и момент выбора цвета не больше момента назначения иконки. Равенство, в том числе
0 и 0, — скрыто. Цвет выбран позже иконки — подчёркивание видно. Атрибута нет
(цвет по умолчанию, старая версия или выключенный плагин цветов) — момент 0, то есть
подчёркивания у проекта с иконкой нет, как раньше. Решение пересчитывается при смене
назначения и при смене атрибута: за ним следит отдельный `MutationObserver` только на
подписях проектов (`attributeFilter`), а не на ленте чата.

Правило привязано к самой иконке: оно сработает, только пока рядом с подписью стоит
элемент иконки с классом `pi-no-underline`. Снятие иконки (в окне «Без иконки» или
`bb genidev-project-icons set <projectId> none`) убирает элемент, и подчёркивание
возвращается без перезагрузки, на классах и стилях подписи ничего не остаётся.
Ошибка «после снятия иконки пропадает подчёркивание» на 0.3.0 вживую не
воспроизвелась (см. «Что дорабатывали»).

## Показ состояний при выборе

Наведение или фокус на иконку запускает по кругу все состояния, для которых у неё
есть кадры, только CSS. Порядок: «в работе» (движение глаз; нужен кадр `left`
и/или `right`), «ждёт вас» (`puzzled`), «ошибка» (`alert`), «готово» (`happy`).
Каждое состояние длится 2,4 с; в «в работе» глаза: прямо 1,28 с, влево 0,4 с,
прямо 0,32 с, вправо 0,4 с. Цикл = 2,4 с × число имеющихся состояний (у иконки с
шестью кадрами 9,6 с, у иконки с тремя 4,8 с; у иконки, у которой есть только один
кадр, показ не меняется). Под сеткой одна строка мелким шрифтом (`.pi-caption`,
высота занята всегда, окно не прыгает): подпись меняется в такт кадрам, потому что
у кадров и подписи одно окно показа и одна задержка на состояние. У иконки без
единого кадра (в том числе своих картинок) подпись «без анимации». При
`prefers-reduced-motion` движения нет, показан основной кадр, подпись «анимация
выключена в системе». Таймеров в JavaScript нет.

## Личный набор (0.4.0)

Иконки, которые нельзя публиковать вместе с плагином, лежат вне него.

- Папка: настройка «Personal icon pack folder» (`packDir`, строка); пусто —
  `~/.bb/plugins_bb/project-icons-pack` (домашняя папка пользователя, под которым
  работает сервер bb). Путь обязан быть абсолютным: относительный хост не сохраняет
  (понятное сообщение), а если он всё же попал в хранилище, набор не читается и в
  `reload-pack` видна причина. Нет папки или `icons.json` — личного набора нет, ошибок нет.
- Формат и проверки те же, что у `assets/icons/` (`loadIconFolder` в `bundled.ts`):
  id, имя файла без путей, тип по первым байтам, до 512 КБ, кадры. Дополнительно
  для набора читаются только файлы, названные в `icons.json`, и только внутри
  папки: настоящий путь (`realpath`) обязан лежать в ней, ссылка наружу отклоняется
  (в том числе сам `icons.json`); ссылка внутри папки допустима.
- Порядок в библиотеке: вшитые, личный набор, свои картинки. Вид `pack`; в окне
  выбора крестика нет, удаление по RPC и CLI отказывает. Кадры, состояния и
  HTTP-адрес `/icon?id=&frame=` те же, что у вшитых.
- Совпал id со вшитой иконкой — побеждает вшитая, в журнале одна строка.
- Набор читается при загрузке, при смене настройки и командой
  `bb genidev-project-icons reload-pack` (сколько прочитано, сколько пропущено, причины;
  `--json`). `icons` выводит `kind` (`builtin`, `pack`, `custom`).
- Закрытые иконки (`leader-*`, `star-*`, `sheikh`, `gg-mascot`) в `assets/icons/` не
  должны попадать: тест `pack.test.ts` читает настоящий `icons.json` и папку и
  падает, если находит такие. У владельца они лежат в личном наборе; идентификаторы
  не менялись, назначенные проектам иконки продолжили работать.

## Свои картинки

- «+» открывает выбор файла (PNG, JPEG, WebP). В браузере картинка вписывается
  в квадрат 96×96 с сохранением пропорций и прозрачности и кодируется в WebP
  (`canvas.toBlob('image/webp', 0.92)`); если браузер вернул не WebP, уходит PNG.
- Сервер проверяет картинку по первым байтам (PNG, JPEG, WebP; SVG и прочее —
  понятная ошибка), у WebP — что длина в заголовке RIFF равна длине файла, размер
  до 512 КБ и до 512 px по стороне. Своих не больше 200.
- `bb genidev-project-icons add <файл> --name <имя>`: `sips` приводит к 96×96 PNG,
  затем `cwebp -q 92 -alpha_q 100` переводит в WebP, если `cwebp` найден в PATH,
  `/opt/homebrew/bin` или `/usr/local/bin`; без `cwebp` остаётся PNG. Программы
  запускаются без оболочки, с таймаутом 20 с, пути — аргументами.
- Сохранённые раньше PNG продолжают отдаваться как PNG.
- Удаление: крестик при наведении (на сенсорных экранах виден всегда) или Delete
  на ячейке, подтверждение внутри окна. Удалённая картинка снимается со всех проектов.

## Состояния и анимация

Состояние считается на клиенте из `experimental_useSidebarThreads()` — живого
списка тредов боковой панели bb (обновляется самим bb, плагин ничего не
опрашивает). Правило в `project-state.ts`; в проекте показывается первое
подходящее состояние сверху вниз:

| # | Состояние | Признак у хотя бы одного треда проекта |
| --- | --- | --- |
| 1 | Ошибка | `status === "error"` и `isUnread === true`, либо `indicator === "unread-error"` |
| 2 | Ждёт владельца | `hasPendingInteraction === true` (агент ждёт разрешения, ответа на вопрос или решения по плану) или `indicator === "waiting-for-input"` |
| 3 | Работает | `status` — `starting`, `active` или `stopping` |
| 4 | Готово, не просмотрено | `indicator === "unread-success"` |
| 5 | Покой | ничего из перечисленного |

Скрытые (`isHidden`) и архивные треды не считаются. Приоритет проверен тестом на
все пары состояний (в обоих порядках тредов) и на все пять сразу.

**По каким данным определяется (проверено на живых данных 24.11.2026).**
Поля треда в боковой панели: `status` (`idle`, `active`, `error`, …),
`indicator` (`none`, `runtime`, `unread-success`, `waiting-for-input`,
`unread-error`, …), `isUnread`, `hasPendingInteraction`. Снимок живого списка
(88 тредов): `idle | none` — 69; `active | runtime` — 7; `error | none | isUnread false`
— 7; `error | none | isUnread true` — 2; `idle | unread-success | isUnread true` — 2;
`idle | background-command` — 1.

- «Готово, не просмотрено» определяется надёжно: `indicator: "unread-success"`
  (тред `thr_v4yp97t558`, проект «Инвестиции в медцентры»; `thr_dg7shznruf`,
  проект Global GG AI), в иконке проекта это видно зелёной точкой.
- «Ошибка»: значение `indicator: "unread-error"` в живых данных не встретилось,
  а у тредов `status: "error"` с `isUnread: true` (`thr_dyd79cmzzt`, проект
  Ostrov Stats; `thr_w48ccxvv7q`, проект Global GG AI) bb оставил
  `indicator: "none"`. Поэтому ошибка берётся из пары `status === "error"` +
  `isUnread`; `unread-error` учитывается на случай, если bb его выставит. Не
  проверено: что статус `error` всегда означает «ход закончился ошибкой», а не,
  например, сбой запуска; прочитанные (`isUnread: false`) ошибочные треды ошибкой
  не считаются (таких 7, они оставляют проект в покое).
- Неоткрытый результат (`unread-success` / `unread-error`) не считается «ждёт»:
  bb отличает его от ожидания ответа, и плагин тоже.
- Что делает `hasPendingInteraction`, сказано в типах SDK: «The agent is blocked
  on the user: an approval or a question». То, что план, ждущий решения, тоже
  попадает сюда, следует из того, что bb показывает его как запрос к владельцу;
  отдельно на живом плане это не проверялось.

Показ в боковой панели (`decoration.ts` + `style.css`, только CSS, без таймеров
в коде; кадры подгружаются, только пока проект не в покое):

| Состояние | Кадр | Метка (правый верхний угол) | Движение |
| --- | --- | --- | --- |
| Ошибка | `alert`, если есть, иначе основной | красная, «!» | иконка вздрагивает раз в 3 с |
| Ждёт владельца | `puzzled`, если есть, иначе основной | жёлтая, «?», всегда | `puzzled` наклоняется раз в 2 с |
| Работает | `left`/`right` (цикл 3 с), без них иконка сдвигается на 1 px | нет | да |
| Готово, не просмотрено | `happy`, если есть, иначе основной | зелёная точка | нет |
| Покой | основной | нет | нет |

- Метки одного размера (9×9 px) и в одном углу, висят на 3 px за краем иконки: не
  перекрывают название (зазор 4 px), строка не меняет ширину. Цвета — в `DESIGN.md`.
- `prefers-reduced-motion` — без движения: «работает» показывает основной кадр,
  остальные состояния — свой кадр и метку.
- настройка плагина «Анимация иконок» (Settings → Installed plugins, или
  `bb plugin config genidev-project-icons set animation false`) выключает
  движение и кадры состояний: иконки показывают основной кадр, метки «?», «!» и
  зелёная точка остаются. Меняется вживую.

В окне выбора проигрывается свой цикл (см. «Показ состояний при выборе»).

### Кадры в наборе

`icons.json`: `{"id","file","name","frames"?}`, где
`frames = {"left"?, "right"?, "puzzled"?, "alert"?, "happy"?}` — файлы в той же папке
(`alert` — испуган: широко раскрытые глаза, открытый рот; `happy` — рад: глаза дугами,
улыбка). Кадр
проверяется так же, как основной файл; битый или отсутствующий кадр
пропускается с записью в лог плагина (`bb plugin logs genidev-project-icons`),
иконка остаётся. Кадр отдаётся по тому же адресу с `&frame=<имя>`.

## Отладочный переключатель

Позволяет задать состояние проекту без настоящих событий. Включается только
вручную, в консоли окна bb:

```js
const k = "genidev-project-icons:debug-state";
localStorage.setItem(k, JSON.stringify({ "proj_xxx": "error", "proj_yyy": "waiting" }));
dispatchEvent(new StorageEvent("storage", { key: k })); // в той же вкладке
```

Значения: `error`, `waiting`, `working`, `done`, `idle` (`idle` гасит настоящее
состояние). Мусор в ключе игнорируется. Выключить: `localStorage.removeItem(k)` и
то же событие. Без ключа переключатель ничего не делает.

## Что не проверено

- Настоящий тред в состоянии «ждёт владельца» вживую: во время проверки такого
  не было; «ждёт» проверено отладочным переключателем и тестами.
- Одновременные состояния у одного проекта — тестом `project-state` (все пары), не
  на живых тредах.
- Кадры `alert` и `happy` у вшитых иконок: в наборе их пока нет (нужны новые
  персонажи с шестью кадрами); без них показывается основной кадр. При проверке
  0.3.0 им временно давали копии существующих кадров, потом их убрали.
- Ошибка вживую проверена на двух настоящих тредах (см. выше), но что такое
  `status: "error"` у bb, в документации SDK не сказано.
- Браузер без кодировщика WebP (запасной PNG) — тестом с поддельным canvas.
- Кадры `left`, `right`, `puzzled` есть у 29 из 30 вшитых иконок; у `armor-hero` их нет.
